## 1. 产品摘要

Enacta 是一个由 Agent 驱动、本地优先、以真实文件为基础的 AI 工作空间。它接收用户的声音、文字、文件和外部数据，理解其中的目标与上下文，并将意图转化为可继续编辑、执行和追踪的知识、计划、任务、自动化流程与应用。

Enacta 不是把笔记、任务管理和 AI 对话简单放在一起。它围绕一条统一的工作链路设计：

```text
声音 / 文字 / 文件 / 外部数据
              ↓
       理解意图与上下文
              ↓
     规划、拆解、组织与执行
              ↓
知识 / 画布 / 任务 / 自动化 / 应用
              ↓
      审核、修改、运行与沉淀
```

一句话定位：

> **Enacta 是一个将你的声音、数据和想法，自动转化为知识、任务、工作流与应用的 Agentic AI Workspace。**

面向用户的简洁表达：

> **说出你想做什么，Enacta 帮你把它变成可执行的成果。**

## 2. 产品愿景

### 2.1 愿景

让人不再被工具结构、操作步骤和信息搬运所限制，而是直接表达目标，由可信的 Agent 与可扩展编辑器共同完成从理解到交付的全过程。

### 2.2 使命

建立一个个人可控、数据可见、能力可扩展的工作系统，使每一个自然语言意图都能被组织成真实文件、明确任务、可审计行动和可持续演进的数字成果。

### 2.3 核心主张

传统软件要求用户先理解工具，再把想法拆成一系列操作。Enacta 反转这一关系：用户先表达意图，系统再选择合适的知识结构、编辑器、任务与执行工具。

产品的长期目标不是“替用户生成一次答案”，而是帮助用户建立可持续工作的成果系统：

- 内容可以继续编辑，而不是停留在聊天记录中。
- 任务可以继续执行和追踪，而不是只得到一份建议。
- 自动化可以重复运行，而不是每次重新描述流程。
- 应用可以继续维护和扩展，而不是生成一次性的演示页面。
- 所有重要变化都有来源、权限、状态与历史依据。

## 3. 用户问题与市场机会

### 3.1 用户当前面临的问题

知识工作通常被割裂在多个工具中：语音记录进入录音应用，灵感进入笔记，事项进入任务工具，资料进入网盘，自动化进入脚本平台，最终产物又进入代码编辑器或建站工具。用户需要不断复制、整理、转换和维护上下文。

AI 虽然降低了内容生成成本，但大量结果仍然停留在聊天窗口里，无法自然进入真实工作环境。用户得到的是答案，而不是一个持续可用的工作对象。

### 3.2 Enacta 的机会

Enacta 将不同入口和不同成果统一到同一套工作内核：

- 用声音和自然语言降低表达成本。
- 用 Agent 理解目标、建立上下文并协调执行。
- 用任务和自动化模块把想法变成行动。
- 用知识、画布和文件沉淀可复用的信息。
- 用可扩展编辑器把新文件类型变成新的业务能力。
- 用应用编辑器将自然语言进一步转化为可运行的软件。

## 4. 目标用户

### 4.1 核心用户

**个人创造者与独立开发者**

需要在灵感、研究、计划、内容、脚本与应用之间快速切换，希望通过一句话或一段声音完成更多实际产出。

**知识工作者与管理者**

需要持续处理会议、资料、计划、任务和项目状态，希望 AI 不只是总结信息，还能创建任务、更新文档并推动后续行动。

**小型团队与创业者**

需要用有限人力完成研究、运营、项目管理、自动化和轻量应用建设，同时希望保留对数据和工作过程的控制。

**高级效率用户**

已经使用 Markdown、脚本、自动化或本地文件工作流，希望获得比封闭 SaaS 更灵活、比传统 IDE 更自然的 Agent 工作环境。

### 4.2 初期重点人群

Enacta 初期应优先服务“愿意使用本地文件、需要同时管理知识与行动、并且愿意让 Agent 参与工作的个人高级用户”。这类用户能够理解产品的独特价值，也更能接受编辑器逐步扩展的产品形态。

## 5. 核心价值

### 5.1 从表达意图到交付成果

用户不必先决定应该打开哪个工具。Enacta 根据表达内容与当前上下文，建议或创建最合适的成果类型，例如 Markdown 文档、画布、任务计划、自动化脚本或应用项目。

### 5.2 知识与行动天然连接

知识不是任务之外的资料库，任务也不是脱离上下文的待办列表。Enacta 允许计划引用知识、任务关联文件、Agent 读取上下文，执行结果再回写到工作空间。

### 5.3 AI 结果成为真实工作对象

Agent 的输出进入可编辑、可保存、可追踪的真实文件和业务编辑器，而不是被锁在对话历史中。用户可以继续修改、运行、分享、版本管理或迁移这些成果。

### 5.4 编辑器即能力扩展

每新增一种编辑器，Enacta 就获得一种新的业务能力。编辑器不仅负责呈现内容，还通过注册表向 Agent 提供受限的上下文、工具、验证规则与变更方式。

### 5.5 本地优先与用户控制

用户文件是事实来源。基础文件操作不依赖云端，外部变化不会被静默覆盖，Agent 的写入需要经过权限、版本与冲突保护。用户可以理解系统修改了什么，也可以撤销或恢复。

## 6. 产品工作模型

Enacta 的产品模型由五层组成。

### 6.1 Capture：捕获

捕获层负责接收用户和外部世界的输入：

- 文字输入与 Agent 对话。
- 持续或按需声音记录、语音转文字与说话人时间线。
- 本地文件、Workspace 内容与用户选定的上下文。
- 日历、邮件、消息、数据库、API、网页订阅等外部数据源。
- 系统事件或用户配置的自动触发条件。

声音模块的重点不是“增加一个语音输入框”，而是提供低摩擦的意图入口。系统应区分原始转写、语义整理、用户确认和后续执行，保留来源与时间信息。

### 6.2 Understand：理解

理解层将输入转化为结构化意图：

- 识别用户是在记录知识、提出问题、创建计划、安排任务、设计流程，还是要求生成应用。
- 结合当前文件、Workspace、历史任务和授权数据源理解上下文。
- 识别目标、限制、截止时间、参与者、依赖项和期望成果。
- 在信息不足或风险较高时请求用户确认。

### 6.3 Plan & Orchestrate：规划与编排

Agent 将复杂目标分解为可执行步骤，并选择合适的编辑器和工具：

- 创建或更新知识文档与画布。
- 建立项目、里程碑、任务、依赖与提醒。
- 生成自动化脚本或工作流，并在权限范围内运行。
- 协调多个专业 Agent 或技能完成研究、设计、实现与验证。
- 追踪执行状态，在失败、冲突或外部变化时调整计划。

### 6.4 Create & Execute：创建与执行

编辑器负责把计划落到具体业务对象上：

- Markdown 编辑器：知识、说明、研究、会议记录与结构化文本。
- IdeaSketch / 画布编辑器：空间化思考、图示、演示与视觉内容。
- 任务管理编辑器：项目、任务、依赖、状态、优先级与进度。
- 自动化脚本编辑器：触发器、数据转换、动作、运行日志与调试。
- 应用编辑器：需求、页面、数据模型、代码、预览、部署与迭代。
- 未来编辑器：通过统一注册机制扩展新的文件格式和业务领域。

### 6.5 Review & Evolve：审核与演进

所有重要产物都进入可审核的生命周期：

- 预览 Agent 即将执行的高风险操作。
- 查看变更差异、来源、运行状态和错误。
- 接受、修改、撤销或重试。
- 将一次成功操作保存为模板、技能或自动化。
- 让知识、计划和应用随着新输入持续更新。

## 7. 核心产品能力

### 7.1 真实文件 Workspace

用户选择一个真实本地目录作为 Workspace。文件内容仍然属于用户，可被其他工具读取、备份和版本管理。Workspace Mode 与 Single File Mode 共用同一套编辑器、解析、保存和安全逻辑。

### 7.2 可扩展编辑器平台

Enacta 使用注册表驱动的编辑器架构。每一种编辑器应声明：

- 支持的文件类型与创建方式。
- 解析、验证、读取和保存规则。
- 可提供给 Agent 的上下文。
- Agent 可以调用的受限工具。
- 变更预览、事务、Undo/Redo 与恢复策略。
- 编辑器专属设置、命令和视觉导航。

通用 Workspace、Agent Runtime 和文件基础设施保持格式无关；编辑器特定逻辑被隔离在各自模块中。

### 7.3 Agent 工作空间

Agent 是跨编辑器的工作伙伴，而不是某个编辑器内部的聊天插件。它理解当前 Workspace 和活动文件，在授权范围内读取信息、建立计划、调用编辑器能力并呈现执行过程。

长期 Agent 工作流包括：

- 单次问答与编辑。
- 多步骤计划与执行。
- 长时任务与后台状态追踪。
- 多 Agent 或多技能协作。
- 事件触发的自动执行。
- 人工审批、异常处理与恢复。

### 7.4 声音输入与语义记录

声音模块将“随时表达”变成 Enacta 的主要入口之一：

- 快速语音输入：替代键盘输入 Agent 指令。
- 连续记录：在用户授权时记录会议、思考或工作日志。
- 原始转写：保留准确时间线和可回溯来源。
- 语义提炼：提取观点、问题、决定、任务和待确认事项。
- 自动落地：根据语义创建 Markdown、画布、任务计划或后续自动化。

声音内容具有较高隐私敏感性，因此录制状态必须明显，保存位置、保留期限、模型处理方式和删除入口必须清晰可控。

### 7.5 外部数据源

外部数据源让 Enacta 不只响应用户主动输入，也能基于真实业务状态工作。连接器可以提供读取、订阅和有限写入能力，例如：

- 日历事件生成准备任务和跟进事项。
- 邮件或消息中的承诺转化为任务。
- 数据库或表格状态变化触发工作流。
- API、RSS 或网页数据形成研究报告和监测任务。
- 代码仓库、工单系统或部署平台同步项目进度。

每个连接器必须明确数据范围、刷新方式、写入权限、凭据管理和失败行为。

### 7.6 任务管理编辑器

任务编辑器是“意图到行动”的核心载体。它不应只是待办清单，而应支持 Agent 理解和执行：

- 项目、目标、里程碑、任务与子任务。
- 状态、优先级、截止时间、负责人和标签。
- 任务依赖、阻塞原因与验收标准。
- 关联知识、画布、脚本、应用和外部数据。
- Agent 计划、执行记录、审核点和产出链接。
- 列表、看板、时间线等不同视图。

### 7.7 自动化脚本编辑器

自动化编辑器将重复工作变成可检查、可测试、可运行的流程：

- 自然语言生成流程或脚本草案。
- 可视化步骤与代码视图协同。
- 触发器、条件、数据映射、动作和错误分支。
- 测试输入、模拟运行、逐步调试和运行日志。
- Secret 隔离、最小权限和执行沙箱。
- 将成功的 Agent 操作固化为可复用自动化。

### 7.8 应用编辑器

应用编辑器代表 Enacta 的长期创造能力。用户用一句话描述目标后，系统协助完成：

1. 澄清目标用户、场景和验收标准。
2. 生成产品结构、页面流程和数据模型。
3. 创建代码、资源和项目文件。
4. 提供实时预览、调试和测试。
5. 管理迭代任务、版本和部署。

应用创建必须仍然遵守 Enacta 的核心原则：产物真实可见、修改可审查、执行有权限边界、用户可以接管和继续维护。

## 8. 典型使用场景

### 8.1 从一段声音生成完整行动计划

用户在通勤途中说：“下个月准备发布新产品，我需要市场调研、落地页、发布内容和每周检查计划。”

Enacta 完成以下工作：

1. 保存并转写原始声音。
2. 提取目标、时间范围与主要交付物。
3. 创建项目说明 Markdown 和产品发布画布。
4. 在任务编辑器中生成里程碑、依赖与每周任务。
5. 请求用户确认关键假设与截止日期。
6. 后续由 Agent 按计划研究、更新文档并推进任务。

### 8.2 从会议记录连接知识与任务

会议结束后，Enacta 将转写内容整理为会议纪要，识别决定、争议、负责人和承诺时间；相关背景进入知识库，行动项进入任务计划，并链接回原始录音与对应时间点。

### 8.3 根据外部数据自动创建工作

用户连接客户反馈表和工单系统。当某类问题在一周内超过阈值时，Enacta 自动创建分析任务，汇总相关记录，生成问题画布，并准备一个修复计划供用户审核。

### 8.4 一句话创建一个应用

用户输入：“为我的读书会创建一个网站，成员可以提交书目、投票并查看每月活动。”

Enacta 创建需求说明、任务计划、数据模型和 Web 应用项目，生成可预览版本；用户继续通过自然语言或应用编辑器调整页面、规则和部署设置。

### 8.5 将个人流程固化为自动化

用户多次让 Agent 把每周会议记录整理成项目周报。Enacta 建议将这套步骤保存为自动化：每周读取指定资料、生成报告、创建待确认项，并在发布前等待用户审批。

## 9. 产品信息架构

Enacta 延续清晰的三栏工作台：

- 左侧：Workspaces、真实文件、数据源与全局入口。
- 中间：当前工作对象的单一前台编辑器。
- 右侧：跨编辑器 Agent、计划、执行活动与审批。

中间区域始终聚焦一个当前对象，避免用大量标签页制造上下文噪音。不同业务能力通过编辑器扩展，而不是在主界面堆叠互不关联的功能模块。

长期可将 Agent 的工作状态统一为：

```text
理解中 → 计划待确认 → 执行中 → 等待输入 → 已完成 / 失败 / 已取消
```

每个状态都应说明当前目标、正在使用的上下文、已经完成的动作、下一步以及是否需要用户决定。

## 11. 产品演进路线

### 阶段 A：可信工作空间基础

目标是建立稳定的真实文件、多编辑器和 Agent 工作台。重点包括 Workspace、安全保存、画布、Markdown、Agent Runtime、编辑器扩展点和一致的桌面体验。

### 阶段 B：Intent-to-Task

引入任务管理编辑器和声音输入，使用户可以从自然语言或录音直接形成知识、计划和任务。建立目标、依赖、验收、审核和执行状态模型。

### 阶段 C：Intent-to-Automation

引入外部数据连接器、自动化脚本编辑器、触发器和安全运行环境。让 Agent 能够基于事件持续推进工作，并把成功操作沉淀为可复用流程。

### 阶段 D：Intent-to-App

引入应用编辑器，将需求、任务、代码、预览、测试和部署连接为统一工作流，实现从一句话到可维护应用的创建体验。

### 阶段 E：个人 Agent 工作系统

让知识、任务、自动化和应用形成持续反馈。Enacta 在用户授权和监督下，根据新声音、新数据和执行结果维护个人或团队的工作系统。

## 12. 设计与架构原则

### 12.1 Files are the source of truth

真实文件是用户内容的事实来源。内部元数据只负责状态、缓存和恢复，不保存另一份正文作为主要来源。

### 12.2 Local-first, connected when useful

核心编辑与文件操作本地可用。网络用于模型、连接器、同步或部署等明确需要联网的能力，并向用户说明其作用。

### 12.3 Dual mode, single core

Workspace Mode 与 Single File Mode 使用同一套编辑器、解析器、保存管线和安全机制，避免功能分裂。

### 12.4 Registry-driven editors

新增业务能力优先通过注册编辑器、文件格式、Agent Extension 和设置贡献完成，不把格式特定逻辑写入通用基础设施。

### 12.5 Human authority over consequential actions

Agent 可以主动建议和准备，但涉及外部写入、删除、运行脚本、发送信息、部署和费用的操作必须遵循清晰的权限与审批策略。

### 12.6 Visible, reversible and auditable

用户需要看到 Agent 使用了什么上下文、修改了什么、执行到哪里以及为何失败。重要变化应可预览、撤销、恢复或重新运行。

### 12.7 Progressive autonomy

自治能力应从“建议”逐步发展到“经确认执行”，再到“在明确规则内自动执行”。自动化程度由用户、任务风险和数据权限共同决定。

### 12.8 One core, many outcomes

知识、任务、自动化与应用不是四个孤立产品。它们共享同一 Workspace、Agent Runtime、权限、上下文、文件安全与执行记录。

## 13. 信任、安全与隐私

Enacta 的 Agent 能力越强，越需要把信任设计为产品基础，而不是附加设置。

### 13.1 数据控制

- 明确本地处理与远程模型处理的边界。
- 用户可以选择哪些文件、录音和数据源进入模型上下文。
- Credential、Secret 和 API Key 使用独立安全存储，不进入工作文件、对话历史或日志。
- 支持查看、导出和删除 Agent 相关数据。

### 13.2 执行权限

- 默认最小权限。
- 读取、修改、删除、发送、运行和部署采用不同权限等级。
- 高风险操作显示目标、影响范围和可恢复性。
- 外部连接器分别授权，不因连接一个来源而获得其他系统权限。

### 13.3 变更安全

- Agent 修改绑定文档版本与内容指纹。
- 外部变化或版本冲突阻止静默覆盖。
- 修改通过编辑器原生事务进入 Undo/Redo 与恢复生命周期。
- 长时任务保留步骤状态、产出和失败点，避免重复副作用。

### 13.4 声音隐私

- 录制状态持续可见。
- 明确原始音频、转写和摘要分别保存在哪里。
- 支持自动保留期限和快速删除。
- 涉及他人声音时提供合规提醒与明确控制。

## 14. 产品差异化

Enacta 的差异不在于单项功能最多，而在于把以下能力组合成同一内核：

1. **意图优先**：用户从目标出发，不必先学习工具结构。
2. **真实成果**：AI 结果进入可编辑、可运行、可迁移的文件和应用。
3. **知识行动一体化**：资料、计划、任务、自动化与产出互相连接。
4. **编辑器扩展业务**：新增编辑器即可新增业务能力，并自然获得 Agent 支持。
5. **本地优先与安全变更**：用户保留数据所有权，Agent 行为可见、可逆、可审计。
6. **从辅助到执行**：产品既能帮助思考，也能在授权范围内推动工作完成。

## 15. 品牌表达

### 15.1 品牌名称

**Enacta** 源自 “enact” 所代表的行动与实现。它强调产品不是停留在记录和生成，而是帮助用户把意图落实为成果。

品牌固定写作 **Enacta**，不使用 `enacta`、`EnActa` 或其他大小写变体。

### 15.2 推荐口号

主口号：

> **Turn intent into outcomes.**

传播口号：

> **Say it. Enacta makes it happen.**

中文表达：

> **说出你的想法，让它真正发生。**

### 15.3 标准产品描述

短版：

> Enacta 是一个将声音、数据和想法转化为知识、任务、工作流与应用的 AI 工作空间。

长版：

> Enacta 是一个由 Agent 驱动、本地优先、以真实文件为基础的 AI 工作空间。它理解用户的声音、文字和外部数据，通过可扩展编辑器自动创建和维护知识、计划、任务、自动化流程与应用，让用户从表达意图直接走向可执行、可审核、可持续演进的成果。

## 16. 成功指标

产品指标应围绕“是否真正帮助用户完成工作”设计，而不只衡量对话次数或生成字数。

### 16.1 核心结果指标

- 从表达意图到创建第一个有效成果的时间。
- 被用户接受、继续编辑或实际执行的 Agent 产物比例。
- 从知识记录转化为任务或自动化的比例。
- 用户完成跨编辑器工作闭环的数量。
- 自动化成功运行并节省重复操作的次数。
- 由 Enacta 创建并持续维护的应用或项目数量。

### 16.2 信任与质量指标

- Agent 变更的接受、修改、撤销和拒绝比例。
- 外部冲突、重复副作用和不可恢复错误的发生率。
- 高风险操作获得正确审批的比例。
- 语音转写与任务提取的用户修正率。
- 长时任务成功完成率、失败可解释率和恢复成功率。

### 16.3 留存信号

- 用户每周主动回到同一 Workspace 的频率。
- 被持续更新而非一次性生成的文件、任务和应用数量。
- 用户创建的连接器、模板、技能和自动化数量。
- Agent 参与的真实完成任务数，而非仅创建任务数。

## 17. 明确边界

Enacta 不以成为传统办公套件的功能集合为目标，也不以完全隐藏文件和代码为目标。

在相关基础设施、权限和验证能力成熟前，以下行为不应默认自治执行：

- 未经确认删除或覆盖重要文件。
- 在未知环境中执行任意本地脚本。
- 自动发送对外消息、提交交易或产生费用。
- 未经审核部署生产应用或修改生产数据。
- 在用户不知情的情况下持续录音或上传声音。
- 将未验证的 AI 推断当作事实写入关键业务系统。

## 18. 与当前 PRD 的关系

当前 `docs/superplan/human/prd.md` 仍是已批准产品范围与实现原则的权威来源，其中已落地的真实文件 Workspace、双模式单内核、延迟元数据、注册表驱动编辑器、本地优先安全写入和通用 Agent 架构，构成 Enacta 的现有基础。

本说明书增加的是 Enacta 的长期品牌定位和能力方向，包括声音输入、任务管理、自动化、外部数据源、更强 Agent 工作流与应用创建。它们需要在后续 PRD 修订、Feature Intake 和经批准的 Superplan 计划中逐项转化为可实施范围。

## 19. 最终定义

Enacta 最终不是一个“带 AI 的笔记工具”，也不是任务工具、自动化平台和应用生成器的简单组合。

> **Enacta 是一个以用户意图为入口、以真实文件为基础、以 Agent 为执行引擎、以可扩展编辑器为能力载体的个人工作系统。**

它的核心承诺是：

> **用户负责表达目标与做出关键决定；Enacta 负责理解、组织、创建、执行和持续推进。**
