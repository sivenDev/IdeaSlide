# F073 RFC：统一 .is 编辑器 JSSDK 与语义化场景操作接口

## 1. 摘要

IdeaSketch（`.is`）目前没有一个稳定、类型化的 JSSDK。画布命令、Excalidraw 原始 API、页面和 Camera 闭包、Agent Tools 以及编辑器绑定分散在不同层级；新增能力通常只能在某一个入口上打补丁。本文提出一个由 IdeaSketch 自有的 `IdeaSketchSdk` facade 统一承载的接口边界，并把文本作为完整场景模型的一部分，而不是独立的临时接口。

所有由 JSSDK、Agent Tool 或应用级语义命令发起、修改已有 Page 的场景写操作都通过一个语义化 `scene.applyPlan()` 事务入口完成；新 Page 的初始 scene 只可作为 `pages.applyPlan()` 中受限且不能指向已有 Page 的 seed/import/duplicate 结果创建。独立文本、形状内文本、文本内容和字号/样式调整，与形状、箭头、绑定、移动、缩放和删除使用同一套 ChangeSet、稳定引用、读取前置条件、版本校验和原生 Excalidraw Undo 路径。Excalidraw 用户原生交互仍走 native authoring path；现有 Agent Tools 和 UI 命令保留兼容层，但不再继续扩大原始 `any` API 的公共契约。

## 2. 背景与问题

当前实现已经具备可复用的安全边界：编辑器绑定了文档身份、revision、source fingerprint、只读状态、取消状态和挂载状态；Agent 的 `apply_drawing_plan`、`apply_layout_plan` 会通过活动 Page 的原生编辑器事务写入，并参与正常的 dirty、auto-save、recovery 和 Undo 流程。F070/F071 证明了语义化形状、箭头、绑定、移动和缩放可以共用这条路径。

但接口仍然是分散的：

| 当前表面 | 已有方法或能力 | 当前问题 | RFC 归类 |
| --- | --- | --- | --- |
| `SlideCanvasCommandApi` | `exportDrawio`、`openImageExport`、`changeCanvasBackground`、`clearCanvas` | 仅是组件级命令，不能被其他调用方复用 | facade 的 `io`、`scene` 命令 |
| 原始 Excalidraw API | 读取 `getSceneElements()`、`getSceneElementsIncludingDeleted()`、`getAppState()`、`getFiles()`；写入 `updateScene()`、`addFiles()`；视图/事件 `setActiveTool()`、`scrollToContent()`、`refresh()`、`setToast()`、`onChange()`、`onScrollChange()`、`onPointerDown()`、`onPointerUp()` | 通过 `any` 传递，暴露底层数据结构，容易绕过文档安全和持久化边界 | 仅保留为内部 adapter；对外提供类型化、受限语义接口 |
| `IdeaSketchEditor` 页面闭包 | `selectPage`、`addPage`、`duplicatePage`、`importPage`、`renamePage`、`reorderPage`、`deletePage` | 页面能力与场景能力没有统一的目标、结果和错误模型 | facade 的 `pages` |
| `IdeaSketchEditor` Camera/导入导出闭包 | `selectCamera`、`deleteCamera`、`reorderCameraList`、`handleAddCamera`、`startPresentation`、`exportActivePageAsExcalidraw`、`exportActivePageAsIdeaSketch`、`handleConvertSelection`、`changeCanvasBackground`、`clearCanvas`、`exportDrawio`、`openImageExport` | 只能通过 React 闭包调用，无法形成可测试的 SDK 契约 | facade 的 `cameras`、`presentation`、`transforms`、`io`、`scene`、`view` |
| IdeaSketch Agent Tools | `read_document_outline`、`read_active_page`、`add_page`、`delete_page`、`reorder_page`、`replace_page_elements`、`apply_drawing_plan`、`apply_layout_plan` | Tool schema 是唯一较完整的语义入口，但只覆盖形状/箭头/布局，缺少文本和统一操作模型 | 兼容适配到 `IdeaSketchSdk` |
| Agent Editor Binding | `buildContext()`、`createToolExecutor()`、`describeChangeSet()`、`applyChangeSet()` | 绑定接口是编辑器内部协议，不是可复用的 JSSDK facade | facade 的 host adapter |
| Camera 私有 API | `getSceneElements()`、`setActiveTool()`、`updateScene()` | 为 Camera 绘制测试和宿主控制服务，不能作为公共 JSSDK | 保持私有，仅由 adapter 使用 |

缺少统一边界会造成四类实际风险：

1. 文本无法和形状、箭头共享同一套引用、绑定和 Undo 语义。
2. 新入口容易复制 revision、只读、取消和外部变更检查，最终出现行为分叉。
3. `any` 原始 API 让调用方可以构造任意 Excalidraw JSON，公共契约会被上游版本牵着走。
4. 页面、Camera、视图、导出和场景修改的能力无法通过 capability 发现、版本化和渐进迁移。

## 3. 目标

1. 提供唯一的、类型化的 `IdeaSketchSdk` facade，覆盖当前 `.is` 编辑器的可复用读取、页面、场景、文本、Camera、视图和导入导出能力。
2. 让独立文本、形状内文本、文本替换、字号和文本样式调整成为一等场景操作。
3. 让所有获准的场景写调用方共用同一个 ChangeSet 校验和编辑器事务边界，同时让 Page 结构、view、presentation 和 IO 使用各自明确的事务或非事务语义。
4. 保留 `page:<id>`、`element:<id>` 等稳定引用，并以 host 签发的 opaque read receipt 绑定实时 Page edit version、revision、source marker 和不可逆 digest，防止过期或伪造写入。
5. 保证一次成功的场景计划对应一次原生 Excalidraw history capture；失败、取消、只读、未读取、跨 Page 或不支持目标时不产生场景变化。
6. 保留现有 Agent Tool 已文档化的输入和行为兼容性，把旧入口适配到新的统一操作模型，并把任意 raw elements 输入隔离到只有显式协商旧 Agent Tool protocol 才可发现的 legacy adapter。
7. 通过 capability/version 协商逐步扩大能力，不把任意 Excalidraw JSON 或文件写入暴露给调用方。

## 4. 非目标

- 本 RFC 不实现代码，也不批准任何具体实现计划。
- 不重做 `.is` 文件格式，不要求已有文件迁移；文本仍以可编辑的原生 Excalidraw 元素保存。
- 不支持富文本 span、Markdown 渲染、图片文字、任意自定义容器或跨 Page 的单事务修改。
- 不把 raw Excalidraw JSON 用作公共 scene read、mutation 或 replace contract；只允许显式、受限的 parse/serialize/import/export bytes 格式边界，不返回可直接提交到 scene transaction 的 raw object。
- 不新增独立的文本编辑器 UI；画布内编辑仍由 Excalidraw 负责。
- 不改变通用 Agent runtime、模型 provider、Thread 或 Tool approval 的职责。
- 不在本阶段承诺把 SDK 发布为独立 npm 包；先在应用内形成稳定边界，待第二个编辑器复用后再评估拆包。

## 5. 决策

### 5.1 统一 facade、方法与序列化操作

`IdeaSketchSdk` 是应用内唯一稳定 JSSDK。TypeScript 方法使用 camelCase；可持久化、可序列化的计划操作使用 kebab-case。方法负责读取、权限、事务和副作用；`operations` 下的 page/element/shape/connector/text/camera/appearance/transform/scene builder 仅构造纯数据，不直接写入，因此不会形成第二条 mutation path。

```text
IdeaSketchSdk
├── session       # getInfo、dispose
├── context       # get、getCapabilities
├── requests      # getMutationResult、reconcile
├── pages         # list、select、validatePlan、applyPlan、parseExcalidraw
├── scene         # read、getElements、requestClearConfirmation、validatePlan、applyPlan
├── operations    # page、element、shape、connector、text、camera、appearance、transform、scene 的纯 builder
├── cameras       # list、select、beginCreate；写操作仍编译为 scene plan
├── selection     # get、set、clear
├── view          # getViewport、focusElements
├── transforms    # convertSelectionStyle
├── presentation  # getState、start、stop、next、previous、goToCamera
├── assets        # listMetadata；v1 不公开 addFiles
├── io            # serialize、用户介导的 active-Page 导入导出和图片导出对话框
└── events        # 高层 context/scene/selection/availability/presentation 事件
```

原始 Excalidraw 实例、`AppState`、DOM event、`updateScene()`、`addFiles()`、`refresh()` 和 toast 只存在于 host/adapter 层。`SlideCanvasCommandApi`、React 闭包、Agent Editor Binding 和 Camera 私有 API 最终都调用 facade 或内部 adapter，不再各自实现校验、绑定和持久化规则。

v1 public method catalog 如下；表内 convenience wrapper 只能组合同表中的 canonical 方法，不能实现独立写入：

| Namespace | 方法 | Scope/副作用 |
| --- | --- | --- |
| `session` | `getInfo()`、`dispose()` | 返回 opaque caller session identity；安全关闭 facade、订阅和 caller-bound token，不改变文档 |
| `context` | `get()`、`getCapabilities()` | 返回当前 document/Page refs、状态、协议和授权能力；不返回 raw model 或 fingerprint source |
| `requests` | `getMutationResult(requestId)`、`reconcile(reconciliationToken)` | caller-bound 的只读幂等结果查询与不确定提交对账 |
| `pages` | `list()`、`select()`、`parseExcalidraw()`、`validatePlan()`、`applyPlan()` | document 读取、非持久 Page 选择、受限解析，以及唯一 Page 结构事务 |
| `scene` | `read()`、`getElements()`、`requestClearConfirmation()`、`validatePlan()`、`applyPlan()` | 有界语义读取、trusted UI 的 host-owned destructive confirmation、纯验证，以及唯一 scene/AppState 持久写事务 |
| `operations` | `page.add/import/duplicate/rename/reorder/delete/createFromSelection`；`element.move/resize/delete`；`shape.create/setStyle/upsertBoundText`；`connector.create/bind/unbind/setStyle/setArrowheads/setPoints`；`text.create/bind/unbind/setContent/setStyle/setLayout`；`camera.create/updateBounds/reorder/delete`；`appearance.setBackground`；`transform.applyStylePreset`；`scene.clear` | 同步纯函数，与 5.6/5.8 operation kind 一一对应，只生成 versioned operation data；不读写编辑器 |
| `cameras` | `list()`、`select()`、`beginCreate()` | `list` 是 scene read 的过滤视图；`select` 是 selection/view wrapper；`beginCreate` 仅 trusted UI，最终提交仍是 `create-camera` |
| `selection` | `get()`、`set()`、`clear()` | 非持久选择状态；只接受 snapshot identity coverage 内的 live refs |
| `view` | `getViewport()`、`focusElements()` | 非持久 viewport 读取/聚焦；不暴露 `AppState` |
| `transforms` | `convertSelectionStyle()` | convenience wrapper；当前 Page 编译为 scene plan，新 Page 编译为 document plan |
| `presentation` | `getState()`、`start()`、`stop()`、`next()`、`previous()`、`goToCamera()` | UI-scoped presentation session；不改 scene、不进入 history |
| `assets` | `listMetadata()` | 分页返回 MIME、尺寸、字节数和引用摘要；v1 无 asset write |
| `io` | `serializeActivePageAsExcalidraw()`、`serializeActivePageAsIdeaSketch()`、`serializeActivePageAsDrawio()`、`exportActivePageAsExcalidraw()`、`exportActivePageAsIdeaSketch()`、`exportActivePageAsDrawio()`、`openImageExportDialog()`、`pickExcalidrawAndAddPage()` | serialize 只返回内容；export/pick 仅用户介导且不可接受任意路径 |
| `events` | `onContextChange()`、`onSceneCommitted()`、`onSelectionChange()`、`onAvailabilityChange()`、`onPresentationStateChange()` | 同步注册并返回 idempotent unsubscribe；payload 仅含稳定 refs、版本和语义摘要 |

host 通过 `createIdeaSketchSdkSession({hostCaller,requestedSdkProtocolVersion,requestedAgentToolProtocolVersion?}) -> Promise<SdkResult<IdeaSketchSdk>>` 创建 facade；`hostCaller` 是 host 内部不可伪造的 caller descriptor，不是外部可提交的 profile/scope。每个 builder 生成带 `kind` 和 `version: 1` 的严格 operation；相同 kind 的字段只在 5.6 或 5.8 的 canonical table 定义一份，builder、Agent schema 和 bridge serializer 不得各自派生变体。除 `operations` builder 和 event subscribe/unsubscribe 外，public read/command 方法均为异步并返回 5.5 的 `SdkResult`。`validatePlan()` 只在 clone 上规范化并返回 diagnostics/preview，不预留锁、不生成 history，`applyPlan()` 始终重新执行全部授权、snapshot 和 postcondition 校验。

### 5.2 调用方权限与 capability

一个 facade 不代表所有调用方权限相同。host 在创建 facade 时绑定不可伪造的 `callerId` 和 caller profile，并按 profile、read-only、挂载状态、桌面环境和当前文档状态强制裁剪能力：

| Profile | 默认能力 | 明确禁止 |
| --- | --- | --- |
| trusted UI | 语义读写、Page 命令、selection、Camera、用户介导 IO、presentation | 任意路径写盘、raw Excalidraw API |
| Agent adapter | 有界 context/scene read、明确 allowlist 的 Page/scene mutation Tools | pointer/scroll、toast、文件选择器、IO、presentation、asset write、legacy raw replace |
| future external caller | 仅显式授权的 public scopes | 未授权 scope、host internal、legacy |
| host internal | hydration、draft sync、layout refresh、Camera pointer preview、toast | 不作为公共或 Agent 契约 |
| legacy adapter | 仅显式协商 Agent Tool protocol v1 的迁移期 caller 调用旧 schema | default/new protocol caller 不可发现或直接调用 |

能力 scope 至少包括 `context.read`、`requests.read`、`document.read`、`document.structure.write`、`document.import.parse`、`scene.read`、`scene.write`、`scene.destructive-clear`、`selection.control`、`view.read`、`view.control`、`presentation.control`、`io.serialize`、`user-mediated-io`、`asset.read`、`events.read`、`host.interaction` 和 `legacy.raw-scene`。`scene.destructive-clear` 只授予 trusted UI，并且不能绕过 host-owned confirmation；`document.import.parse` 只允许受 capability limits 约束的内存 bytes/string 解析，不包含 picker 或文件路径权限。`context.getCapabilities()` 返回：

- `sdkProtocolVersion`：JSSDK 协议版本，使用 `major.minor`；major 不兼容，minor 只能增加能力；
- Agent profile 的 `agentToolProtocolVersion` 与 `toolSchemaDigest`；两者与 SDK/document version 独立，并在 Turn 创建时固定；
- `documentFormatVersion`：当前 `.is` 文件格式版本，与 SDK 版本独立；
- caller profile 和已强制授权的 scopes；
- 静态 `supported` 方法、操作、元素类型、容器、样式字段和限制；
- 动态 `available` 状态，例如 editor mounted、writable、desktop dialogs、presentation；
- 当前 limits，例如读取分页、计划字节数、操作数、文本长度、字号和尺寸。

facade 创建时由 host 协商并绑定一个 `sdkProtocolVersion`；所有可序列化 Tool/bridge envelope 也必须显式携带该版本。host 可以向后兼容同 major 的旧 minor，请求高于 host 的 minor 时只能使用双方 capability 交集；major 不同直接拒绝。Agent Extension/Tool catalog 另行声明 `agentToolProtocolVersion`：现有 8-Tool schema 定义为 legacy v1，新 semantic catalog 定义为 v2。创建 Tool executor/Turn 时精确协商并捕获该版本、caller profile 和 `toolSchemaDigest`，再绑定到每个 ChangeSet envelope；版本不得在 Turn 中途改变，也不得根据 Tool 名称或 payload 猜测。未知 major 或 schema digest mismatch 返回 `protocol_mismatch`，不得从 v2 静默回退到 v1。未知 operation、字段、style 或未授权 scope 一律 fail closed。`requiredCapabilities` 只是调用方声明“缺少即拒绝”的额外前置条件，绝不能扩大 host 已授予的 scope。可选能力只有在 capability 明确返回时才能使用；Agent Tools 从协商版本和 allowlist 动态投影，不能通过知道 JSSDK 方法名获得额外权限。

### 5.3 稳定引用、分页读取与 read receipt

公共 identity 使用 branded string，而不是裸 id：

```text
DocumentRef = document:<id>
PageRef    = page:<id>
ElementRef = element:<id>
CameraRef  = camera:<id>
AssetRef   = asset:<id>
TempRef    = temp:<caller-defined-id>
ParsedPageDraftRef = import:<host-issued-id>
StableRef  = DocumentRef | PageRef | ElementRef | CameraRef | AssetRef
PageScopedRef = { pageRef: PageRef, ref: ElementRef | CameraRef | AssetRef }
CreatedRefTarget = PageRef | PageScopedRef
```

`DocumentRef` 绑定 document session，`PageRef` 在该 session 内唯一；`ElementRef`、`CameraRef` 和 `AssetRef` 只有与 `PageRef` 和 read receipt 组合时才唯一，不同 Page 可以存在相同底层 id。Camera 虽由原生 rectangle 表示，但公共契约只能使用 `CameraRef`。普通 shape/text/connector 操作必须拒绝 Camera；adapter 内可维护 `CameraRef` 到底层 element id 的一一映射。

`scene.read({ pageRef, cursor?, limit? })` 返回有界语义摘要及 opaque `snapshotId`：

```text
{
  snapshotId,
  pageRef,
  pageEditVersion,
  complete,
  nextCursor?,
  coverage: {
    identityRefs,
    mutationReadyRefs
  },
  elements
}
```

- v1 scene/camera/selection/view mutation-capable surface 只针对当前 active mounted Page；`scene.read.pageRef` 不等于 `context.activePageRef` 时返回 `cross_page_target`，不得隐式选择 Page。调用方需要先使用 `pages.select()`，再重新读取 context/scene。
- 第一次读取以 `pageRef` 创建 snapshot；后续 `cursor` 是 caller/page/snapshot-bound opaque token，并继续同一个 `snapshotId`。`complete` 表示该 snapshot 的累计分页覆盖已经包含全部 live elements，而不是只表示当前响应页已满。
- `snapshotId` 由 host 签发，绑定 document session、Page、document revision/status/source marker、实时 Page edit version、native interaction epoch、document/page digest、caller 和累计 coverage；调用方不能构造或修改。
- `identityRefs` 只证明调用方见过元素 identity；只有 `mutationReadyRefs` 证明目标及完整关系闭包已被原子读取，才可用于 mutation。每个元素摘要同时返回 `relationsComplete`；分页不能把半个闭包标成 complete。
- shape closure 至少包含 bound text、所有 attached arrows、这些 arrows 的另一端 target 及反向记录；arrow closure 至少包含 start/end target、反向记录和 arrow-bound text；group/frame 关系也必须完整。闭包超过限制时整体拒绝，不能把 identity-only ref 升级为 mutation-ready。
- `scene.getElements({ snapshotId, refs })` 用于按 ref 补读并把完整关系闭包加入 `mutationReadyRefs`；不存在、已删除或不在 snapshot 对应 Page 的 ref 明确报错。
- `pages.list()` 返回独立的 opaque `documentSnapshotId`；分页 cursor 保持同一 document snapshot。`scene.read()` 和 `assets.listMetadata()` 同样提供 cursor，不能只返回无法继续读取的 `truncated`。
- 引用已有元素的 operation 必须使用同一 snapshot 的 `mutationReadyRefs`。`clear-scene`、完整 Camera 排序等全局操作必须基于 `complete=true` 的 snapshot。
- `TempRef` 不需要 read receipt，但只能引用同一计划中位于当前操作之前的创建结果。
- mutation result 中返回的 created/updated ref 只提供 identity，不把它们自动升级为后续请求的 `mutationReadyRefs`；成功提交会使原 snapshot stale，任何后续 scene mutation 都必须重新读取 fresh snapshot/关系闭包。
- pointer transform、原生 text edit、IME composition 或 Excalidraw native history/action 开始时，host 立即推进 native interaction epoch，使此前 scene snapshot 对 mutation stale；这些交互结束并稳定产生新的 Page edit version 前，`scene.read()` 和 `scene.applyPlan()` 返回 `editor_busy`，不能签发或提交基于 transient scene 的 mutation receipt。
- snapshot、cursor、parsed import draft 和 reconciliation token 都按 caller 隔离，不能跨 facade/profile、document session 或 Page 复用；scene/document 发生相关变化后 snapshot 立即 stale。

opaque digest 使用带版本的 canonical 定义，snapshot stale、mutation before/after 和 reconciliation 必须使用完全相同的算法：

- Page digest 覆盖按 z-order 排列的 including-deleted elements；每个元素的全部持久字段，包括 text/style/binding/customData/version；files 的 id、持久 metadata 和内容 hash；以及持久 AppState allowlist，至少包含 `viewBackgroundColor`。
- Page digest 不覆盖 selection、viewport、zoom、active tool、dialog、toast 或 Camera preview 等非持久 UI 状态。
- Document digest 覆盖 `.is` format version、Page id/title/order、每个 Page digest 和其他持久 document-level metadata。
- digest 对外最多作为固定长度不可逆值返回，不能复用当前返回完整 Page JSON 的内部 `sourceFingerprint` 实现。

### 5.4 两类 mutation transaction 与非 mutation 命令

#### 5.4.1 Page-scoped scene transaction

所有由 JSSDK、Agent Tool 或应用级语义命令发起、修改已有 Page 的 programmatic 持久 scene/AppState 写入，包括 Camera 数据和背景色，唯一进入 `scene.applyPlan()`：

```text
scene.applyPlan({
  requestId,
  snapshotId,
  operations,
  requiredCapabilities?,
  signal?
}) -> SdkResult<SceneMutationResult>
```

Excalidraw 工具产生的用户原生画图、文本编辑、拖动、缩放和删除仍走 native authoring path：`onChange → EditorSession → dirty/auto-save/recovery`。它不属于第二条 JSSDK mutation path；每次 native commit 都更新 Page edit version 并使相关 snapshot/target stale。创建新 Page 时，`pages.applyPlan()` 可以通过本 RFC 定义的 bounded initial seed、validated import token、duplicate 或 create-from-selection 生成该新 Page 的初始 scene；这些 document operations 不得修改任何已有 Page，也不得形成可复用的 scene mutation bypass。host 从 snapshot 恢复内部 target envelope，其中至少包含 document id、Page id、editor session token、base revision、document status、source marker、document/page digest 和 Page edit version。调用方不直接提交这些可伪造字段。`signal` 是 JS 调用形式；bridge/Agent 使用等价的 host cancellation token。

提交顺序是规范性的：在 clone 上规范化 → 解析全部 ref 和关系闭包 → 使用 native factory/mutation/binding/geometry helper 构造 → `restoreElements` 做尺寸恢复而不是任意 JSON 合法化 → 校验 postconditions → 再次同步校验 active binding、mounted Page、snapshot、native interaction epoch、read-only、外部变更和 cancellation，并确认没有 pointer transform、text editing、IME composition、Camera preview 以外的 native tool transaction 或 native history/action 正在进行 → 在校验与提交之间不发生 `await` → 一次 `updateScene({captureUpdate: IMMEDIATELY})` → 读取提交后 Page digest 对账。busy/stale 路径不得调用 `updateScene()`；programmatic commit 不得与 native authoring commit 共享或合并 history capture。

scene 与 Page apply 共用 document-session-scoped mutation coordinator。相同 caller/request 的并发调用共享同一 in-flight 结果；不同请求在 commit 边界串行化，并在轮到提交时重新校验 snapshot，因此后到的旧 snapshot 会明确 stale，而不是覆盖先到结果。final validation 与 commit 之间不得让出事件循环。

所有 operation 按数组顺序在同一 clone 上执行，后项看到前项结果；任一 operation、关系闭包或 postcondition 失败会拒绝整个 plan，不允许 partial apply。取消只在 commit 前保证无写入；一旦 commit 已发生，晚到的 cancellation 不能把成功降级成 cancelled。

成功计划只产生一次原生 Excalidraw history capture，并进入现有 dirty、auto-save、recovery 和安全保存流程。`applied` 表示已进入编辑器内存和 Undo history，不表示已经 durable save。Camera pointer preview 必须使用 `NEVER`，只在最终创建时进入一次 `IMMEDIATELY` capture。

#### 5.4.2 Document/Page transaction

Page 结构写入唯一进入：

```text
pages.applyPlan({
  requestId,
  documentSnapshotId,
  operations,
  sceneSnapshotId?,      # 只有 create-page-from-selection 需要
  signal?
}) -> SdkResult<DocumentMutationResult>
```

一个计划原子地应用 `add-page`、`import-page`、`duplicate-page`、`rename-page`、`reorder-page`、`delete-page` 或 `create-page-from-selection`，然后进入文档 session 的 dirty、auto-save、recovery 和外部变更保护。`import-page` 只接受 `pages.parseExcalidraw()` 返回的 caller/session-bound `ParsedPageDraftRef`；不接受 raw elements。涉及 selection closure 的 composite 同时重新校验 document 与 scene snapshot，任一 stale 都不提交。Page transaction 不伪装成 Excalidraw canvas history。

引用现有 Page 的 operation 必须使用同一 `documentSnapshotId` 已覆盖的 PageRef；`reorder-page` 必须基于 complete document snapshot，`add-page`/`import-page` 仍需要 snapshot 作为 document revision receipt。`pages.list()` 签发 snapshot 时使用包含当前 mounted draft 的 persisted projection，而不是陈旧 model；`pages.applyPlan()` 在 coordinator 内先 flush/合并最新 Page edit version，再比较 canonical document digest，语义变化则 `snapshot_stale`，不得从旧 document clone 覆盖未 flush scene。

`pages.select({pageRef})` 是非持久导航，不要求 document snapshot 或 requestId。host 先 flush 当前 draft，再在同一 active document session 中重新确认 PageRef 仍存在后切换；flush 不能让一个正常的 select request 自己变 stale。

document history 是否可用必须由 `getCapabilities().available.documentUndo` 和 mutation result 明确报告；没有该能力时 UI、Agent 和 SDK 不能声称 Page 操作可由 native canvas Undo 撤销。B027 已移除 F036 的 Agent-only snapshot/history 栈：Agent scene mutation 与 UI programmatic scene mutation 一样只使用一次 Excalidraw native capture；Agent Page add/delete/reorder 等 document structure mutation 当前报告 document history unavailable，不能伪造 Undo。Page selection 是非持久编辑器状态，不进入 `pages.applyPlan()`，不标记 dirty。

#### 5.4.3 View、presentation 与 IO

selection、viewport、active tool、presentation、dialog 和 export 不产生 ChangeSet/history。它们仍返回统一 `SdkResult`，并检查 availability 和 caller scope。Agent 的编辑器 mutation 保留当前 direct-apply 语义：Tool 先生成内部 immutable ChangeSet envelope（内部 `proposed` 仅表示尚未提交），trusted direct-apply adapter 再校验并立即应用；本 RFC 不恢复 Change Review 或人工 Apply/Reject。非编辑器的不可逆 Tool approval 不受影响。

任何需要 flush mounted draft、签发 document/scene mutation receipt 或创建 export/presentation private snapshot 的方法，都必须应用同一 native interaction busy guard；不得在 pointer transform、text edit、IME composition 或 native history/action 进行中捕获 transient state。host-owned Camera preview 只按 5.7.4 的隔离规则例外处理。

### 5.5 Result、错误和幂等

除纯 builder 和事件订阅外，所有 public 方法都是异步的，返回 discriminated result；正常拒绝、取消和不可用不使用静默 `return`：

```text
SdkResult<T> =
  { status: "succeeded", value: T }
  | { status: "cancelled", error: { code: "cancelled_before_commit", message, retryable } }
  | { status: "rejected", error: { code, message, operationIndex?, ref?, retryable } }
  | { status: "indeterminate", error, reconciliationToken }
```

scene/document mutation 的 `value` 至少包含：`changeSetId`、`requestId`、`outcome: applied|noop`、before/after opaque digest 和 edit version、`createdRefs: Record<TempRef, CreatedRefTarget>`、page-qualified 的 `updatedRefs`、`deletedRefs`、`cascadedRefs`、逐 operation result、diagnostics，以及：

```text
history: {
  nativeCanvas: "created" | "none" | "unavailable",
  document: "created" | "none" | "unavailable",
  agentCustom: "not-supported"
}
```

普通 UI scene 与 Agent scene 的 `nativeCanvas="created"`；当前 Page structure mutation 的 `document="unavailable"`；未来只有 capability 明确启用 document history 才能返回 `created`。容器扩张、绑定文本、箭头重算、Camera order 重写和级联删除都必须出现在机器可读结果中。`noop` 的所有 entry 都是 `none`，不创建 history。

稳定错误码至少包括：`invalid_request`、`internal_error`、`protocol_mismatch`、`unsupported_operation`、`capability_denied`、`confirmation_required`、`editor_unavailable`、`editor_busy`、`session_closed`、`presentation_session_not_found`、`read_only`、`snapshot_required`、`snapshot_stale`、`incomplete_read`、`target_not_found`、`cross_page_target`、`relation_conflict`、`locked_target`、`limit_exceeded`、`import_token_expired`、`request_not_found`、`idempotency_conflict`、`request_ledger_full`、`cancelled_before_commit`、`external_change` 和 `commit_indeterminate`。commit 前内部异常只能返回 `rejected/internal_error` 且保证无写入；commit 边界后的异常只能先对账再进入 `indeterminate`。

所有 mutation 的 `requestId` 必填。幂等 ledger 的 key 是 active document session + caller session id + request id；同 id、同 canonical payload 返回原结果且不再 capture，同 id、不同 payload 返回 `idempotency_conflict`。`succeeded/cancelled/rejected/indeterminate` 都按原 payload 保留到 caller session 关闭；重试已拒绝或取消的业务必须使用新 request id。每个 caller session 最多接受 512 个唯一 mutation request，容量耗尽时拒绝新请求而不驱逐旧记录。Agent `callId` 映射为 request id，ChangeSet id 由 host 派生。

`session.getInfo()` 返回 opaque caller session id、协商版本和 lifecycle state。`session.dispose()` 只有在没有 in-flight mutation、Camera pointer creation 或无法安全取消并 join 的 picker/host interaction，且没有 unresolved `indeterminate` request 时才能成功；否则分别返回 `editor_busy` 或 `commit_indeterminate`。若该 caller session 拥有 active Presentation，dispose 必须在 event subscriptions 仍有效时先原子停止播放、退出 fullscreen、清理 keyboard listener/animation/timer，并发出最终 `onPresentationStateChange(stopped)`；随后才失效 `presentationSessionId`、旧 snapshot、cursor、confirmation receipt、import/reconciliation token 和所有现有 event subscription。任一 cleanup 失败返回 `editor_busy` 或 `internal_error`，facade 保持 active，不能进入 half-disposed 状态。成功后 `getInfo()` 返回 disposed state，重复 `dispose()` 返回 succeeded/noop，新的 event subscribe 返回 inert idempotent unsubscribe，其他 async 方法返回 `session_closed`。ledger full 时，caller 先安全 dispose，再由 host 使用同一不可伪造 caller descriptor 调用 `createIdeaSketchSdkSession()` 创建新 session；新 session 重新协商能力，不继承 ledger/token，也不能借重建提升 scope。外部 caller 不能自行构造 host caller、修改 profile 或绕过 unresolved ledger。

若 commit 调用后无法确认结果，先在 host 内用 after digest 对账；仍无法判断时才返回 `indeterminate` 和 reconciliation token。`requests.reconcile()` 只读地检查 live scene/document 与 ledger，收敛为原 request 的 `succeeded` 或 `rejected`；若仍 indeterminate，则消费旧 token 并返回新的 successor token。`getMutationResult()` 只读取 ledger，不推进 reconciliation。在收敛前禁止以新 request id 重放同一业务意图、关闭持有 ledger 的 document session 或通过 facade 重新绑定丢弃该记录；caller UI 消失时 unresolved ledger 仍至少保留到 document session 安全关闭。

#### 5.6.1 v1 canonical operations

| 分组 | Operation | 目标与主要字段 | 规范语义 |

`clear-scene` 的确认发生在构造 plan 之前。trusted UI 调用 `scene.requestClearConfirmation({snapshotId,scope})`；host 必须验证 complete snapshot 和 `scene.destructive-clear`，显示由 host 控制且明确列出 scope/locked/imported/Camera 影响的确认界面，并在用户确认后返回绑定 caller、document/Page、snapshot、scope 和短过期时间的 opaque `confirmationReceipt`。用户拒绝或关闭界面返回 `cancelled`。receipt 只能用于完全匹配的 `clear-scene`，在首次授权通过的 apply attempt 中原子消费；相同 `requestId` 的幂等查询返回 ledger 原结果而不再次消费，stale、取消或失败后发起新 request 必须重新读取和确认。Agent、future external caller、缺少 `scene.destructive-clear` 或缺少有效 receipt 的调用一律拒绝。成功结果把 scope 内所有 live refs（`content-only` 不含 Camera，`all-elements` 含 Camera；两者都含 locked/imported）列入 `deletedRefs`，关系级联另列 `cascadedRefs`。

| 类型/状态 | v1 允许 | 必须拒绝或仅保留 |
| --- | --- | --- |
| rectangle/ellipse/diamond | create、move、resize、style、text binding、delete、arrow target | locked、损坏关系或未读 target |
| standalone text | create、move、content/style/layout、bind、delete | 直接 resize；使用 text layout/font size |
| shape-bound text | content/style、unbind、delete；随 rectangle/ellipse/diamond container 隐式移动/布局 | 单独 move/resize、再绑定到另一容器 |

| Camera | 专用 create/update/order/delete、read/select/present | 任意普通 shape/text/arrow/style/binding operation |
| imported arrow-bound text | read、preserve、随 connector geometry 重新布局、正确 delete/Undo | v1 不支持新建/绑定，且 text content/style/layout mutation 返回 `unsupported_operation`；connector mutation 不得分离或损坏 label |
| line/freedraw/image/frame/embeddable | read、导出、保存、未涉及时原样保留；显式全场 `clear-scene` 可 soft delete | 其他 v1 semantic mutation；未来 capability 启用前 fail closed |

v1 主动把新建 bound text 容器限制为 rectangle、ellipse 和 diamond；这是 IdeaSketch 的限制，不是 Excalidraw 的能力说明。后续 reserved operation 包括 `create-line`、`create-image`、`create-frame`、`rotate-element`、`duplicate-elements`、`set-z-order`、`group-elements`、`ungroup-elements`、`set-frame-membership`、`set-locked`、`set-link` 和 `restore-element`。这些名称在 capability 返回 false 时必须报 `unsupported_operation`，不能静默降级为 raw replace。

### 5.7 Text、binding、delete 与 geometry invariants

#### 5.7.1 Text model

- 公共字段使用语义枚举：font family 例如 `hand-drawn|normal|code`，由 adapter 映射上游数字；颜色映射到底层 `strokeColor`，opacity 使用 0–100，line height 使用比例值。允许值、默认值与 font-size/width 上限必须由 capability 返回。
- 原生 text 的 `text`、`originalText`、`fontSize`、`fontFamily`、`textAlign`、`verticalAlign`、`lineHeight`、`autoResize`、`containerId` 和 bounds 全部由 adapter 作为一个一致模型维护，调用方不能提交上游数字枚举或派生字段。adapter 负责上游版本实际要求的渲染度量；它们不构成公共或持久字段。
- `create-text` 的 x/y 是 angle=0 的文本 bounds 左上角。未提供 width 时 `autoResize=true`；提供 bounded width 时启用 SDK 定义的 wrapping，`autoResize=false`，由 native measurement 计算 display text、width 和 height。
- `set-text` 同时更新 `originalText`；不得只 patch 已换行的 `text`。font、font size、line height、width 或内容变化后必须重新测量。
- standalone text 可设置 horizontal `textAlign`，`verticalAlign` 固定为 top；shape-bound text 可同时设置 `textAlign`/`verticalAlign`，但宽度和位置由容器布局拥有。两者都不允许直接 patch `text`、height、`containerId`、派生度量或上游内部 font id。imported arrow-bound text 不属于这两个可写目标。
- shape-bound text 不另设含糊的 placement 字段。v1 的 overflow policy 固定为 `grow-container`：文本溢出时允许原生扩大容器；容器和受影响箭头列入隐式 `updatedRefs`，一次 Undo 恢复整个闭包。

#### 5.7.2 Text binding 与级联

- 每个容器最多一个 live bound text；`text.containerId` 与容器 `{id,type:"text"}` 反向记录必须同时更新。
- `bind-text` 只接受独立、未删除、未锁定 text 和受支持 shape。已绑定到其他容器时拒绝；迁移绑定必须先 `unbind-text`。
- 绑定时由 native helper 计算 angle、位置、尺寸、alignment 和合法 z-order。单边损坏、多重 bound text、missing/deleted container 一律 `relation_conflict`，不得在普通 operation 中猜测修复。
- `unbind-text` 把 `containerId` 设为 null，只移除对应反向记录，保留内容、样式和世界坐标，按独立文本规则重新测量；text/container 都列入 `updatedRefs`。
- 删除 text 时 soft delete text 并清理 container 反向记录。删除 container 时 container 与 bound text 一起 soft delete；指向 container 的箭头保留但对应端点解绑并重新计算。删除 arrow 时从 start/end target 清理反向记录；已有 arrow label 即使 v1 不创建，也必须按原生关系一起正确删除。所有隐式变化进入 `deletedRefs/cascadedRefs/updatedRefs`。

#### 5.7.3 Arrow 与 geometry

- `bind-arrow` 支持已有和新建 arrow。omitted endpoint 表示保持不变；明确 null 不作为解绑语义。改绑时先清理旧 target 反向记录，再同时更新新 target、focus、gap、fixed point 和箭头端点 geometry。
- endpoint patch 使用显式 `{ endpoint: start|end, targetRef }`；一个计划可以包含两个 patch。重复 endpoint、空 patch 或用 null 表示解绑一律拒绝。v1 的 `set-connector-points` 只接受没有 start/end shape binding 的 arrow；存在任一 endpoint binding 时返回 `relation_conflict`。该 operation 不得改绑、解绑或分离 arrow-bound text；若存在 imported arrow label，adapter 必须通过 native geometry/text helper 重新计算其位置、尺寸和 wrapping，保持 `containerId` 与反向记录不变，并把 label 列入 `updatedRefs`。未来如支持 bound route，使用只接受 interior vertices 的独立 operation，端点仍由 native binding 派生。
- 两端绑定同一 shape 时，shape `boundElements` 只有一条 arrow 记录；解绑一端但另一端仍指向该 shape 时不得删除这条记录。
- `unbind-arrow` 保留解绑前端点的世界坐标并重新规范化 local points，不得让线端跳变；已有 arrow label 保持关系和布局。
- binding target 必须是已读、live、unlocked、非 Camera 的 rectangle/ellipse/diamond。`restoreElements({repairBindings:true})` 不是完整 arrow binding 算法；adapter 必须使用 native helper 或等价完整算法，并在 restore 后验证双向不变量。
- `move-element` 使用 Page 坐标 delta；`resize-element` 使用绝对 width/height 和 top-left anchor，以保持现有 layout Tool 行为。v1 对 angle 非 0、group/frame membership 或不支持类型拒绝，而不是直接改 x/y/width/height。

#### 5.7.4 Scene postconditions

成功提交后必须保证：所有 element id（含 tombstone）唯一且新建元素不复用历史 id；每容器最多一个 live bound text；所有 live element 的 live binding 双向对称，且任何 live element 都不指向 missing/deleted target；Camera 形态、order 和 style 合法；未涉及的 elements、files、viewport、zoom、active tool、dialog 和 selection 保持不变（只清除已删除 refs）；scene plan 不新增、删除或改写 files；version/versionNonce/updated 使用 native mutation 语义。tombstone 按 Excalidraw native deletion/history payload 保留，不参与 live relation 对称性判定，也不得因无关 operation 被重写；删除 operation 只更新 native helper 要求的 live counterpart 和删除闭包。任何 postcondition 失败都不得提交。

Camera 必须保持 rectangle、angle=0、host-owned `customData.type="camera"`、受控 style、非 locked、非 group/frame member 且不可绑定；bounds 最小值和页面 Camera 数量由 capability 返回。合法 live Camera order 必须是有限、正数且唯一，但为兼容历史文件允许空洞。`set-camera-order` 必须提交所有 live CameraRefs 并基于 complete snapshot。省略 `atIndex` 的 `create-camera` 使用 `max(existingOrder)+1` append（空列表为 1），不得改写已有 Camera order 或仅因历史空洞失败；指定 `atIndex` 时按当前 order 排列在 `0..cameraCount` 内插入，并要求 complete snapshot 与全部 live CameraRefs 已在 `mutationReadyRefs`。`delete-camera` 同样要求 complete snapshot 与全部 live Camera mutation-ready，并在 soft delete 后重排剩余 Camera。只有 indexed insert、delete 和显式 `set-camera-order` 把结果规范化为从 1 开始连续唯一；这些操作导致 order 改变的所有已有 Camera 都进入 `updatedRefs` 和对应 operation result，`cascadedRefs` 只用于删除关系级联，不用于普通 order 更新。

Camera pointer preview 是 host ephemeral element，带不可伪造的内部标记，并始终排除出 semantic read、snapshot coverage、digest、plan clone、持久化和 scene postcondition。取消时以 `NEVER` 移除；完成时先以 `NEVER` 移除 preview，再重新验证 canonical scene projection，最后仅对 `create-camera` 做一次 `IMMEDIATELY` capture。preview 期间其他 programmatic mutation 可以基于排除 preview 的 projection 执行；若 host 无法保证隔离则返回 `editor_busy`。

### 5.8 Page、Camera、selection、transform、IO 与 event methods

#### 5.8.1 Page contract

| 方法/operation | v1 语义 |
| --- | --- |
| `pages.list({cursor?,limit?})` | 返回有序摘要、累计 complete 状态和同一 `documentSnapshotId` |
| `pages.select({pageRef})` | flush 当前 draft 后在 active document session 内重新验证并切换；不标记 dirty；无效 ref 拒绝 |
| `add-page` | `ref: TempRef`、可选 title 和 bounded `initialScene`；默认名按现有顺序生成并默认选中新 Page，不接受 raw elements |
| `import-page` | `ref: TempRef`、`parsedPageDraftRef`、可选 title；消费未过期 token，新建并选择 Page，完整保留已验证 imported elements/files/persistent AppState |
| `duplicate-page` | `ref: TempRef`、`sourcePageRef`、可选 title；完整复制 elements、files、持久 AppState 和 Camera 顺序，生成新 Page id 并清空 selection |
| `rename-page` | `pageRef`、title；trim 后 1–120 字符，空值或超限拒绝 |
| `reorder-page` | `pageRef`、zero-based `toIndex`；要求 complete document snapshot，越界拒绝而不是静默 clamp |
| `delete-page` | `pageRef`；文档至少保留一页，删除 active Page 后选择原位置的下一页，否则上一页 |
| `pages.parseExcalidraw(input)` | 只解析调用方已提供的 JSON/bytes，执行格式版本、元素数、单/总文件大小和 binding 校验，返回有过期时间的一次性 `ParsedPageDraftRef`，不打开文件选择器 |
| `create-page-from-selection` | `ref: TempRef`、`sourcePageRef`、`selectedRefs`、`preset: formal`；基于 scene snapshot 复制显式选择闭包和相关 files 到新 Page |

`initialScene` 复用 5.6 的 exact operation schema，但只允许 `create-shape`、`create-arrow`、`create-text`、append-only `create-camera`（不得提供 `atIndex`）、`bind-arrow`、`bind-text` 和 `set-background`；除 Page 本身外只能引用同一 seed 中更早创建的 TempRef，不接受 StableRef、snapshot、delete/update/clear 或 files。seed 在 document transaction 的 detached new-Page clone 上执行全部 scene postconditions，失败则整个 Page plan 不提交，也不能成为修改已有 Page 的旁路。

整个 Page plan（包括所有 `initialScene`）内的 TempRef 必须唯一。所有新建 Page 的 TempRef→PageRef 和 `initialScene` 的 element/camera TempRef→`{pageRef,ref}` 都进入 `createdRefs`。duplicate 保留 Page 内 element ids，跨 Page identity 由 PageRef+snapshot 消歧。旧 `add_page({title,elements:any[]})` 与 `replace_page_elements` 一样，只保留在 trusted deprecated adapter；新 JSSDK 和 Agent 新 schema 不接受任意 elements JSON。

#### 5.8.2 Camera、selection 与 transform

- `cameras.list({snapshotId,cursor?,limit?})` 是 scene snapshot 的 Camera 过滤视图和唯一 Camera 查询；返回的每个 CameraRef 原子并入同一 snapshot 的 `identityRefs`，但不自动成为 mutation-ready。程序化写入只通过 scene plan 的 Camera operations。
- `cameras.beginCreate({requestId,snapshotId,atIndex?,signal?})` 是 trusted UI 命令：启动 host-only pointer preview，Page/document 切换或取消会以 `NEVER` 清理预览且不写入；完成时移除 preview、重新校验 snapshot，编译 `create-camera` 并走一次 canonical scene transaction。指定 `atIndex` 前必须通过 `cameras.list` 与 `scene.getElements` 使 complete snapshot 内的全部 live Camera mutation-ready；append 不要求完整 Camera coverage。
- `cameras.select({snapshotId,cameraRef})` 通过 `selection.set()` 和 `view.focusElements()` 实现，不形成额外状态协议。
- `selection.get({snapshotId})` 返回 `{selectionVersion, refs}`，并把返回的 selected refs 原子并入同一 snapshot 的 `identityRefs`，但不自动升级为 `mutationReadyRefs`。`selection.set({snapshotId,refs})`、`selection.clear({snapshotId})` 与 `view.focusElements({snapshotId,refs,fit?,animate?,durationMs?})` 都绑定同一 active Page snapshot，`set/focus` 只接受 `identityRefs` 内的 live refs，因此可以选择/聚焦只读的 imported element。`view.getViewport({snapshotId})` 只返回该 Page 的语义化 bounds、zoom 和 visible refs 摘要，visible refs 不改变 coverage。selection/viewport change 不使 scene snapshot stale；任何 transform/mutation 的 `selectedRefs` 仍必须显式传入并全部属于 `mutationReadyRefs`，不能依赖 commit 时的当前 selection。payload 不暴露 AppState。Agent 默认没有 selection/view scope。
- `transforms.convertSelectionStyle({requestId,snapshotId,selectedRefs,target,preset:"formal",documentSnapshotId?})` 不重读当前选择；wrapper 必须先用 `scene.getElements()` 补齐这些显式 refs 的关系闭包，无法升级为 mutation-ready 时返回 `incomplete_read`。`target:"current-page"` 编译为 `apply-style-preset`，`target:"new-page"` 编译为 `create-page-from-selection` 并要求 document snapshot。两条路径分别遵守 scene/document transaction。
- `presentation.start({mode:"preview"|"fullscreen",pageRef,cameraRef?})` 先 flush 当前 Page，再要求 `pageRef === context.activePageRef`；不相等返回 `cross_page_target`，不得隐式选择或加载其他 Page。host 从 post-flush active Page canonical scene 创建私有 presentation snapshot，验证 Camera 后返回 `presentationSessionId`；同一 facade 已有 running session 时返回 `editor_busy`。`getState/stop/next/previous` 接受该 session id，foreign/expired id 返回 `presentation_session_not_found`；`stop` 对刚停止的同一 session id 幂等，`next/previous` 在首尾返回 succeeded/noop 而不循环。`goToCamera({presentationSessionId,cameraRef})` 只接受 session 启动时捕获的 CameraRef。session 始终绑定启动时的 active Page；Page/document 切换必须先停止 session 并发出 `onPresentationStateChange(stopped)`，再切换 context。状态通过 `getState` 和 presentation event 暴露；键盘事件继续在 capture phase 处理，所有方法都不改变 scene、selection 或 history。

#### 5.8.3 IO、asset 与 event

- `io.serializeActivePageAsExcalidraw()`、`serializeActivePageAsIdeaSketch()` 和 `serializeActivePageAsDrawio()` 先 flush 当前 mounted draft，再从 post-flush canonical projection 创建私有 export snapshot，只返回 bytes/blob 和摘要，不写文件、不创建 history。
- `io.exportActivePageAsExcalidraw()`、`exportActivePageAsIdeaSketch()` 和 `exportActivePageAsDrawio()` 仅 trusted UI，通过用户介导 picker/download 写出，不接受任意路径，并返回 succeeded/cancelled/rejected；picker 必须使用与 serialize 相同的 post-flush private export snapshot，并有明确 in-flight 去重。
- `io.openImageExportDialog()` 精确对应当前 `openImageExport`，不是直接 `exportImage()`；需要 mounted canvas 和 UI scope。
- `io.pickExcalidrawAndAddPage({requestId,signal?})` 是 trusted UI 的 user-mediated composite，内部获取 document snapshot、调用 picker、`pages.parseExcalidraw` 和 `import-page`；若 picker 期间 document snapshot 过期则不提交，取消、parse failure、stale 和 desktop unavailable 可区分。
- `assets.listMetadata({snapshotId,cursor?,limit?})` 只返回当前 Page receipt 内的受限 metadata。v1 不公开 asset add/create-image；原始 `addFiles()` 只用于 hydration/import adapter，避免出现无引用 asset。
- 默认 public events 只有 `onContextChange`、`onSceneCommitted`、`onSelectionChange`、`onAvailabilityChange`、`onPresentationStateChange`，同一 facade 内按事件序列单调编号；presentation payload 包含 session id、mode、running/stopped、active CameraRef、index/count。Page/document 切换先停止 active presentation 并发出 stopped event，再原子解除旧 target、使其 snapshot/token stale 并绑定新 context，最后分发 context change；event callback 不能在新 context 下继续使用旧 receipt。pointer、scroll、raw `onChange`、refresh 和 toast 属于 host internal；若未来开放，只能返回受限语义 payload，不能返回 DOM Event/AppState。

### 5.10 兼容与退场

迁移不改变 `.is` 文件格式；文本、Camera 和 tombstone 仍是可编辑的原生 Excalidraw 数据。旧 UI/Agent 入口先改为 adapter，再按 caller 迁移；legacy adapter 只选择协商后的 schema/profile 并翻译 envelope。旧 major 所需的 version-pinned compatibility normalize/build strategy 必须注册在 canonical pipeline 内；最终 authorization/target validation/postcondition/commit 始终共用该 pipeline，adapter 不得拥有独立 normalize/build/commit、`updateScene` 或文件写路径。

兼容通过明确的 Agent Tool protocol major 管理，而不是让同一 schema 静默改变。显式协商的 v1 executor 在迁移窗口内保留全部 8 个 Tool 名称、当前 `add_page(title,elements)`、`replace_page_elements` 和旧 `apply_layout_plan` target 范围；v2 才启用 semantic add-page、JSSDK v1 类型收紧和默认不发现 raw replace。v1 compatibility strategy 最终仍进入同一个 document mutation coordinator、active mounted editor/native capture 或 document reducer boundary。所有调用方迁移且至少经过一个稳定版本后才能删除 Tool protocol v1。

迁移窗口内，只有显式协商 Agent Tool protocol v1 的 pinned caller 才能按旧 Tool catalog 发现 legacy raw schema 并由 host 路由到 compatibility strategy；default/v2 Agent profile 始终没有 `legacy.raw-scene` scope，也不能发现 raw replace。legacy 调用仍必须通过现有 revision/status/source/read-only/cancellation/direct-apply 守卫；active Page scene 写继续只产生一次 native capture，Page structure 写继续如实报告无 document Undo，不能借兼容名绕过 canonical persistence boundary。

## 6. 已考虑的重要替代方案

### 方案 A：只在 `apply_drawing_plan` 上增加文本字段

拒绝。它能最快覆盖独立文本和形状文本，但会继续把 JSSDK、Agent、页面命令和原始 Excalidraw API 分割开，无法解决统一版本、能力发现、事务和迁移问题。

### 方案 B：新增一个独立 `TextSdk` 或 `apply_text_plan`

拒绝作为架构主线。可以保留 `apply_text_plan` 作为便利别名或兼容 Tool，但文本与形状容器、箭头、布局和 Undo 有共同的场景关系，独立事务会产生重复校验和绑定不一致。

### 方案 C：直接把 Excalidraw API 作为公共 JSSDK

拒绝。调用方将依赖上游版本和任意 JSON，能够绕过 revision、外部变更、只读和持久化守卫，也无法对文本容器关系提供稳定语义保证。

### 方案 D：所有修改都使用整页 JSON replace

拒绝作为默认方式。整页替换无法表达最小意图，容易覆盖并发或无关元素，且不利于稳定引用、单步 Undo 和可观察的变更摘要。遗留 replace 仅作为受限兼容能力保留。

### 方案 E：立即发布独立 npm SDK 并一次性移除旧接口

暂缓。当前只有一个编辑器真正消费该边界，立即拆包会固化尚未经过第二编辑器验证的契约并增加迁移风险。先形成应用内 facade，再以 capability 和版本作为外部化前提。

## 7. 风险与缓解措施

| 风险 | 缓解措施 |
| --- | --- |
| facade 范围过大，公共 API 难以演进 | 完整 method catalog、caller-scoped capability、独立协议版本和 deprecated adapter；所有可序列化 schema 严格校验 |
| text/container/arrow 关系损坏 | clone 上使用 native factory/binding/geometry helper，显式维护双向关系和级联，restore 后验证全部 postconditions，失败不提交 |
| Camera 被普通 shape 路径修改或绕过 Undo | 公开 `CameraRef` 和专用 operations；普通 element operation 拒绝 Camera；preview 用 `NEVER`，最终写入统一一次 `IMMEDIATELY` |
| Agent、UI 或网络桥重复应用同一计划 | caller-session-scoped `requestId` ledger、payload collision 检测、一次性 native capture 和 reconciliation；重复请求返回原结果 |
| 过期或伪造读取覆盖实时/外部修改 | host-signed scene/document snapshot 绑定 Page edit version、revision、source marker 和 opaque digests；提交前进行同步复检 |
| 分页遗漏关系导致局部写破坏大场景 | cursor 累计 coverage、按 ref 完整补读关系闭包、全局操作要求 complete snapshot，超限闭包整体拒绝 |
| Page、scene、view 历史语义混淆 | 明确 scene native Undo、当前不可用的 document history 与无历史命令三类边界；遵守 B027，不恢复 Agent-only history |
| 幂等表有界或提交状态不确定 | 容量耗尽 fail closed、不驱逐旧记录；允许安全换 caller session；`requests.reconcile` 在重放前完成对账 |
| 兼容 adapter 与新 facade 行为分叉 | adapter 只选 versioned schema/profile 并翻译 envelope；version-pinned normalize/build strategy 注册在 canonical pipeline 内，authorization/validate/commit 不能分叉 |
| 原始 Excalidraw 上游升级破坏字段 | 将上游类型和 `updateScene` 细节隔离在 adapter；对外只承诺 IdeaSketch 自有协议和语义枚举 |
| 新能力被误用于任意写文件或提权 | capability 按 caller 强制裁剪；SDK 无任意路径参数，导出/导入仅 trusted UI 的用户介导流程，Agent 不获得 IO |

## 8. 发布、回滚与验证边界

### 发布顺序

1. 先建立 protocol、typed facade、caller capability、snapshot/result/idempotency contract 和内部 adapter，不改变旧入口的可观察行为。
2. 建立 canonical scene transaction 与 operation catalog，优先验证 text、binding、Camera、delete cascade 和 geometry 不变量。
3. 将 Agent Tools 适配到 facade，保持 direct apply；active Page scene mutation 只产生一次 Excalidraw native capture，Page structure mutation 如实报告 document history unavailable；legacy raw schema 仅对显式协商 Tool protocol v1 的 pinned caller 可发现，对 default/v2 catalog 不可发现。
4. 将 UI Page/Camera/selection/presentation/IO 命令逐步切换到 facade，并保留可回退的兼容 adapter。
5. 在完整 `.is` 保存、重开、scene native Undo/Redo、Page mutation 无虚假 Undo、auto-save、recovery、外部变更和用户取消流程中验证后，再宣布 JSSDK v1 稳定。
6. 稳定版本后再评估移除原始 `any` 暴露、遗留 replace 和应用内 facade 的外部拆包。

### 回滚边界

发布必须允许按 caller/namespace 切回旧兼容 adapter，不能在同一 namespace 同时启用两条 programmatic 写路径。不需要迁移或回滚 `.is` 文件，因为文本、Camera 和 tombstone 仍是原生可编辑元素。若某个新 scene 操作已经成功提交，使用 Excalidraw native Undo；Page structure mutation 当前无 document Undo，只能通过后续反向命令或既有 recovery/safe-write 流程恢复，不能声称 Agent-only Undo，也不通过直接文件覆盖回滚。

### 必须保留的验证证据

- 当前 `SlideCanvasCommandApi`、Excalidraw API 使用、Page/Camera/transform/export 闭包、Agent binding 和 8 个 Agent Tools 均在归属矩阵中有唯一分类、可见性和兼容策略。
- capability contract 证明 SDK/Agent Tool/document version 分离、supported/available 分离，Tool protocol v1/v2 catalog 与 schema digest 在 Turn 固定，且 trusted UI、Agent、external、host、legacy 获得不同的强制 scope。
- scene/document snapshot 的分页累计 coverage、Camera/selection identity coverage、关系闭包补读、native interaction epoch、stale/不可伪造约束和 raw fingerprint 不泄漏有 contract tests。
- canonical `scene.applyPlan()` 对形状、箭头、绑定、布局、文本、Camera、背景和清理使用同一套 target/snapshot/取消/只读/外部变更校验；pointer/text/IME/native history 进行中返回 busy 且不提交，成功只产生一次独立 native capture。
- 文本原生字段、measurement、overflow、shape-bound text、imported arrow label 随 connector geometry 重排、双向 live binding、Arrow geometry、Camera complete-order coverage、soft delete/tombstone history payload、无关 elements/files/AppState 保留均有自动化测试和保存重开/Undo 证据。
- Page add/import/duplicate/rename/reorder/delete 和 selection-to-new-page composite 有 document snapshot、未 flush draft、至少一页、选择、dirty、无虚假 document/Agent Undo 及 stale 失败测试。
- request ledger 的重复同 payload、冲突 payload、容量耗尽、terminal outcome、indeterminate reconciliation，以及 `session.dispose`/安全重建和 token/subscription 失效有测试；running Presentation dispose 还要证明 stopped event 先于 unsubscribe、fullscreen/keyboard/animation/timer 已清理、旧 session id 失效，cleanup 失败时 facade 保持 active。
- malformed、未读取/不完整读取、过期、跨 Page、普通 locked target、只读、取消、切换文档、超限和 unsupported target 请求均无场景或文档变化；唯一例外是 trusted UI 持有效 receipt 的 destructive clear，并验证其完整 deleted refs。
- IO 测试区分 serialize、用户取消、picker 期间 stale、desktop unavailable 和禁止任意路径；presentation 只允许当前 active Page、切 Page 前发 stopped event，view/event 不写持久状态。
- TypeScript build、相关 Agent/editor contract tests、保存重开、auto-save/recovery、外部变更和 `git diff --check` 通过。

## 9. 可观察的批准条件

RFC 进入 `approved` 前，需要确认以下决策已经被接受：

- 接受完整 public method catalog 与 caller profile/scope 矩阵；原始 Excalidraw API、DOM event、toast、refresh 和 hydration 仅限内部 adapter。
- 接受 `scene.applyPlan()` 是 JSSDK、Agent Tool 和应用级语义命令修改已有 Page 的所有 programmatic scene/AppState/Camera 持久写的唯一事务入口；Excalidraw 用户原生交互仍走 native authoring path。`pages.applyPlan()` 是 Page 结构和 detached new-Page initial seed/import/duplicate 的唯一 programmatic 事务入口，不能修改已有 Page scene；view/presentation/IO 不创建编辑 history。
- 接受 host-signed scene/document snapshots、分页累计 coverage、Camera/selection identity coverage、按 ref 完整关系补读、native interaction epoch 和 opaque digest；调用方不得直接提交 revision/fingerprint/source 字段，native authoring 进行中不得 programmatic commit。
- 接受统一 `SdkResult`、稳定错误码、必填 `requestId`、caller-session ledger、容量耗尽策略、indeterminate reconciliation，以及可调用的 session dispose/host 重建生命周期；dispose 必须先终止 owned Presentation 和清理长生命周期 host resource，失败不得 half-dispose。
- 接受 `create-text`、`bind-text`、`upsert-bound-text`、`set-text`、`set-text-style`、`set-text-layout` 与形状/箭头/布局操作共用 ChangeSet、稳定引用和一次 native Undo capture。
- 接受 v1 新建 bound text 只支持 rectangle/ellipse/diamond；arrow label 的 text content/style/layout 不可写，但 connector geometry 修改必须保持绑定并重新布局；文本原生字段、measurement 和固定 `grow-container` overflow 由 adapter 维护。
- 接受 Arrow 双向 live binding/geometry、Camera 专用 refs/operations/complete-order coverage、soft delete/tombstone history payload、delete cascade 和元素类型 fail-closed 矩阵。
- 接受 `clear-scene` 只有 trusted UI 在持 `scene.destructive-clear` 和 host confirmation receipt 时才能删除 scope 内 locked/imported/Camera elements；其他调用方和普通 mutation 均拒绝 locked target。
- 接受 F036 direct apply 与 B027 native canvas Undo 边界，不恢复 Change Review 或 Agent-only history；Agent 只获得动态 Tool allowlist，Page structure mutation 不宣称可撤销。
- 接受 Presentation 只能从 post-flush 当前 active Page 启动，session 绑定该 Page，Page/document 切换必须先停止并发出 presentation state event。
- 接受 `agentToolProtocolVersion` 与 SDK/document version 独立，Tool protocol v1 在迁移期保留当前 8-Tool catalog/schema，v2 使用 semantic catalog；版本和 schema digest 在 Turn 创建时固定，不得中途改变或静默降级。`replace_page_elements` 与 raw `add_page.elements` 只对显式协商 v1 的 pinned caller 可发现，对 default/v2 caller 不可发现。
- 接受 import/export 只有 semantic parse/serialize 或 trusted UI 用户介导路径，公共 SDK 不接受任意文件路径；`.is` format 不迁移。
- 接受 RFC 批准后仍需另行创建并审批新的实现计划；RFC 本身不授权编码或发布。
